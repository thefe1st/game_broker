# Bootstrap flow checks — explicit test doubles

Run from repository root:

```bash
dotnet test Tools/FlowChecks/FlowChecks.csproj
```

This project compiles the **actual Core, PrototypeBootstrap partials, VoiceSession,
Dialogue providers and OfficeInteractable** with narrow substitutes for UnityEngine,
OfficeScene, player controls and BrokerTheme. `GUI.Click` consumes one enabled
button label; labels are recorded, not rendered. Lifecycle methods are invoked
explicitly. JSON is serialized through System.Text.Json, NOT Unity JsonUtility.

Tests exercise menu/intro/panel clock gates, confirmation/cancellation, next-client
selection, exactly-once day settlement, savings carry, mode reset isolation,
completed-intro reload, hidden-city routing and failed-save retry. Default flow
must not send provider requests.

The suite now has 66 cases, including end-call confirmation/cancel, draft retention,
voice-stop vs call-end separation, focus/pause callback ordering, explicit resume to
the desk, and no new speech request for replies received during pause. Focus/pause
callbacks are invoked by the tests, NOT generated by an actual window manager.
Microphone permission dialogs and platform focus behavior still require Unity.

This is NOT a Unity compile or build. The actual scene geometry, font metrics,
GUI event ordering, input backend, renderer, colliders, audio, JsonUtility and
OS file replacement behavior need separate checks in Unity. Passing tests only
support the specific modeled controller flows, not every runtime interaction.

Shared narrow voice doubles live in `Tools/VoiceChecks/UnityFakes.cs`.
`BootstrapFakes.cs` extends them only in this project. The voice-only suite does
not compile the scene/GUI substitutes.

Work-day cases also cover the intro-completion lock, explicit transfer/cancel, separate
files, employee desk tabs, rotating appointments, exactly-once settlement, continuation
after resetting the intro (including fresh bootstrap), origin-only reset, write-failure
retry, and ten successive work days. This is still not a real Unity scene or JsonUtility test.

Notebook cases verify six-client read-only viewing, clock/file/network isolation,
active-call draft retention, separate today/completed status, empty/history tabs,
personal vs employer money, seven-report pruning and newest-first display after reload,
pause/focus return, guarded opening, and explicit unsaved-progress warnings.
These assertions record GUI text and modeled flow, not rendered layout or real font clipping.

Complaint cases cover GUI sale blocking/repair, separate report obligations via Core tests,
next-contact persistence, fresh reload, mid-day restart, failed-save retry without duplicate
relationship gain, and legacy-shaped JSON import to separate v2 without modifying v1 bytes.
