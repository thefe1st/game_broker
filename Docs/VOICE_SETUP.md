# Голос: как проверить на Windows

Это экспериментальная версия под Unity 6000.3.14f1. Голос добавлен в исходники, но пока не проверен в Unity и на реальном API. Текстовый режим остаётся рабочим запасным вариантом.

## 0. Сначала проверьте микрофон без API

Для этого **не нужны Node.js, сервер, ключ или включение внешнего голоса**.

1. Откройте проект в Unity **6000.3.14f1**. При необходимости: **Broker → Create 3D Office Scene**, затем Play.
2. На утреннем экране нажмите **«Проверить микрофон без API»**. Во время дня это окно также доступно через **Esc → «Микрофон и связь»** и на рабочем столе: «Офис» → «Проверить микрофон и связь».
3. Если устройств несколько, выберите нужное кнопкой **«Следующий микрофон»**. «Обновить список» перечитывает устройства; выбор действует до закрытия игры и используется также для настоящих звонков.
4. Наденьте наушники, нажмите **«Записать тест микрофона»**, скажите короткую фразу. При запросе разрешения разрешите доступ к микрофону.
5. Индикатор показывает текущий уровень сигнала. Нажмите **«Закончить тестовую запись»**, затем **«Прослушать запись»**.
6. Убедитесь, что слышен именно ваш голос, без сильного шума или перегруза. Сам индикатор не отличает речь от шума. Через 20 секунд запись завершится автоматически.
7. **«Вернуться / Esc»** останавливает операции и удаляет тестовую запись из памяти. «Остановить / удалить тестовую запись» делает это, не закрывая окно.

Звук теста не записывается на диск, не отправляется на сервер и не превращается в игровую реплику. Экономика и звонок не меняются; игровой таймер стоит. Прослушивание можно повторить до удаления записи. Новая запись, смена устройства, обновление списка и проверка шлюза также удаляют предыдущую тестовую запись.

Кнопка **«Проверить сервер :8787»** выполняет только локальный `GET /health`. Она показывает, доступен ли шлюз и включён ли его голосовой режим. Провайдер не вызывается, ключ/оплата не проверяются. Последняя ошибка реального голоса остаётся внизу окна диагностики, даже если текущую операцию остановили.

## 1. Подготовьте API

Нужен ключ провайдера, который поддерживает OpenAI-совместимые **Audio Transcriptions** и **Audio Speech** с PCM16 WAV. Наличие текстового API недостаточно. Настройки по умолчанию рассчитаны на OpenAI Audio API; доступность, оплату и поддержку моделей нужно проверить у своего провайдера. API оплачивается отдельно от подписки на чат.

Ключ храните только локально. Не отправляйте его в чат или GitHub. Если такого ключа пока нет, оставьте внешний голос выключенным и используйте локальную проверку выше.

## 2. Создайте локальный .env

В папке `Server` скопируйте `.env.example` в `.env`. В Windows удобнее открыть PowerShell в этой папке и выполнить:

```powershell
Copy-Item .env.example .env
notepad .env
```

Не делайте это поверх существующего настроенного .env — отредактируйте его. Внутри задайте следующие строки (значение ключа подставьте только у себя):

```dotenv
MODE=mock
VOICE_MODE=ai
API_KEY=YOUR_LOCAL_API_KEY
API_BASE_URL=https://api.openai.com/v1/
STT_MODEL=whisper-1
TTS_MODEL=tts-1
TTS_VOICE=alloy
PORT=8787
```

Здесь MODE=mock оставляет диалоги локальными, но распознавание и озвучка выполняются настоящим внешним сервисом. Это минимальный вариант для проверки голоса. Для другого совместимого провайдера поменяйте URL, модели и голос на поддерживаемые им значения. Избегайте имени `.env.txt`.

## 3. Запустите сервер

Нужен Node.js 24. В терминале в папке Server:

```powershell
npm.cmd start
```

Если старый сервер уже работал, остановите его Ctrl+C и запустите заново: настройки читаются при старте. Оставьте окно открытым. На http://127.0.0.1:8787/health должно появиться:

```json
{"status":"ok","mode":"mock","voice":"ai"}
```

Это показывает настройки сервера, но не доказывает действительность ключа: реальный запрос выполняется только при использовании голоса.

## 4. Проверьте Unity

1. Откройте обновлённый проект в Unity 6000.3.14f1.
2. Если сцены нет: Broker → Create 3D Office Scene.
3. Нажмите Play, начните день и откройте рабочий стол через телефон/монитор (E). Лучше использовать наушники, чтобы микрофон не записывал клиента.
4. Откройте вкладку **«Офис»**. Переключите **«Выкл · Голос → внешний API»** в «Вкл». ИИ-формулировки можно оставить выключенными. Вернитесь на вкладку **«Звонки»**.
5. Позвоните Борису: приложение попытается озвучить приветствие.
6. Нажмите **«Записать голос»**, скажите «Какая у вас цель?», затем **«Распознать»**. Если появится запрос доступа к микрофону, разрешите его.
7. Дождитесь текста в поле ввода. Проверьте/исправьте его и нажмите **«Сказать»**.
8. Борис должен ответить текстом и голосом. Повторите с риском и комиссией. После «Предложить сделку» он задаст вопрос о резерве: ответьте на него, затем закройте сделку. Голосовой текст проходит те же правила, что ручной ввод: см. `Docs/NEGOTIATIONS.md`.

Микрофон включается только по кнопке, запись автоматически заканчивается через 20 секунд. «Остановить голос» отменяет запись/обработку/воспроизведение. Завершение дня тоже отменяет операции. Используется микрофон, выбранный в окне диагностики; без выбора — первый доступный. Переключение во время записи недоступно.

## Если что-то не работает

- Нет кнопок голоса: открыт старый проект или архив.
- Voice disabled в health: проверьте VOICE_MODE в .env и перезапустите сервер.
- Не найден микрофон: проверьте выбранное устройство и разрешение доступа для настольных приложений в настройках Windows. Не отключайте системную защиту.
- Не слышно: проверьте системную громкость и выключенную кнопку Mute Audio в окне Game редактора Unity.
- Ошибка распознавания/озвучки: проверьте запуск сервера, правильность URL/ключа, оплату API, поддержку моделей и WAV. Приложение не показывает секретные детали провайдера в ошибках.
- HTTPS policy / Insecure connection в Unity: сообщите точный текст ошибки; локальный HTTP-путь пока рассчитан прежде всего на Editor и требует отдельной проверки в сборке.

Пришлите сообщение ошибки и красные строки Console без ключа API. По ним можно будет исправить интеграцию. Настройки провайдера, кроме секретов, полезны для диагностики.


## Автоматические проверки и оставшиеся ручные проверки

- `dotnet test Tools/CoreChecks/CoreChecks.csproj`: 216 engine-free тестов, в том числе уровень сигнала и безопасные сообщения диагностики.
- `dotnet test Tools/VoiceChecks/VoiceChecks.csproj`: 16 тестов голосового потока **с тестовыми заменами Unity API**. Проверяют отсутствие сетевых запросов при локальном тесте, автостоп, выбор устройства, удаление записи, ошибки и отбрасывание отменённых ответов. Это не проверка микрофона, динамиков или JsonUtility в Unity.
- `cd Server; npm test`: 35 тестов шлюза с подставным внешним API.
- Требуется вручную проверить разрешения Windows, реальные устройства, компоновку окна, возврат в игру, внешнее распознавание и озвучку. Unity Editor в среде разработки недоступен; успешный тест с заменами API не считается запуском в Unity.
