# Архитектура

## Core
`BrokerDay` — авторитетные правила рабочего дня. Три ClientRecord и два EmployeeRecord доступны через read-only списки; поля состояния меняет core. Открытым может быть только один звонок. Истории и UI не входят в core. Расчёт денег, доверия, расходов, заданий, происшествий и окончания дня детерминированный. `WaveCodec` обрабатывает PCM16 WAV без UnityEngine.

Поступления учитываются в Earned/Cash, покупки и платные решения — в Spent/Cash. TotalExpenses — аренда, зарплаты и согласованные отложенные расходы. FinalBalance = Cash - TotalExpenses. Это предотвращает двойное списание текущих покупок в отчёте.

`AdvanceTime` обновляет сотрудников и поднимает одно происшествие. При PendingEvent время и задания стоят. UI дополнительно не вызывает AdvanceTime во время обучения, чтения журнала и ожидания внешней операции. Настроение влияет на длительность работы и премию побочного обзвона.

## Runtime
`PrototypeBootstrap` пока оркестрирует UI и асинхронные реплики. У каждого клиента свои списки истории/сообщений. Смена клиента запрещена во время активного звонка, внешнего ответа или происшествия. Реплика сначала обрабатывается C#-правилами, затем необязательно перефразируется. Повторный запрос не применяется повторно к деньгам. Ревизия и CancellationToken блокируют устаревшие ответы.

`OfficeScene` создаёт из примитивов отдельный набор на расстоянии от начала сцены. Собственная камера рендерит его в центральную область. GUI рисует фон вокруг, не поверх viewport. Геометрия — временная редактируемая заготовка, без готовых сторонних моделей. `BrokerTheme` владеет цветами, стилями и созданными текстурами. Макет 1440×960 масштабируется с letterboxing; мобильного layout нет.

`VoiceSession` сохраняет экспериментальный двухкнопочный ввод, предварительный просмотр текста, явное согласие и AudioSource. Общий синтетический голос для всех клиентов. Голосовые команды команды пока отсутствуют. Запись только по кнопке до 20 секунд, без сохранения сырого звука на диск.

## Server
Loopback Node.js, без публичного доступа/авторизации. `/dialogue` принимает boris/inna/artem и выбирает фиксированную persona на сервере. Пользовательская история вкладывается в user-данные, не становится системной ролью. Ответ ограничен JSON-полем reply. Проверка формата не гарантирует смысловой корректности модели.

`/transcribe` и `/speech` включаются отдельно через VOICE_MODE=ai. Секреты только на сервере, ограничения размеров/длительности, отмена, таймауты и лимиты запросов сохранены. Без ключа основная игра полностью локальна.

## Тестирование
`Tools/CoreChecks/CoreChecks.csproj` компилирует engine-free Core и те же NUnit-тесты, что доступны Unity Test Runner. Выполнены 49 C#-тестов на .NET 8, включая старые регрессионные и WAV-тесты. Выполнены 35 Node.js-тестов с fake fetch. GitHub Actions содержит оба задания.

Эти тесты не компилируют runtime против UnityEngine и не заменяют Unity PlayMode, визуальный QA, проверку разрешений микрофона, настоящий API и desktop-сборку. Пока эти проверки недоступны. Следующий технический шаг — импорт в Unity и визуальная проверка всех экранов/модалок.


## Итерация 3D: прогулка вместо постоянного dashboard

`OfficeNavigation` (Core) хранит только режим: Explore/Desk/Employee/Coffee/Upgrade/Exit/Pause. Открытие окна не тратит деньги и не завершает день. Дополнительные NUnit-тесты проверяют эти переходы и отсутствие изменения звонка.

`FirstPersonOfficeController` использует CharacterController, гравитацию и raycast до 2.7 м. Нет прыжков/тряски камеры. Компонент `OfficeInteractable` связывает предмет с разрешённой станцией, заголовком и номером сотрудника. Игрок игнорируется собственным лучом. Стол и стены имеют коллайдеры; декоративные элементы — нет.

`OfficeInput` предпочитает новый Input System при ENABLE_INPUT_SYSTEM, иначе использует legacy backend при ENABLE_LEGACY_INPUT_MANAGER. Оба не опрашиваются одновременно. Input System 1.11.2 добавлен в manifest и runtime asmdef. Настройки PlayerSettings не переписываются автоматически. Для legacy добавлены Mouse X/Y. При отсутствии ввода часы exploration не идут, доступен запасной dashboard.

`OfficeScene` создаёт перспективную камеру игрока и отдельную обзорную камеру для Desk. Они переключаются, а потолок скрывается для обзорной камеры. В мире GUI не закрывает 3D-вид большим фоном. У сотрудников простые составные модели и движение рук, без рига/NavMesh. Сцена пока генерируется в Play Mode и не запекается в .unity.

`PrototypeBootstrap.World.cs` — partial-часть контроллера: HUD и физические станции. При закрытии окна мышь захватывается явным действием игрока. Esc из рабочего экрана отменяет внешнее ожидание/запись, но не откатывает обработанную реплику и не заканчивает звонок. Станция двери требует отдельного подтверждения.

49 C#-тестов выполнены на .NET 8, 35 Node.js-тестов — без реального API. Синтаксис всех C# проверен с четырьмя конфигурациями preprocessor. Это всё ещё не проверка Unity API, CharacterController, взаимодействий, input backend, камера/свет и визуального качества. Нужен Unity PlayMode.
