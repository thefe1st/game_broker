# Архитектура

## Core
`BrokerDay` — авторитетные правила рабочего дня. Три ClientRecord и два EmployeeRecord доступны через read-only списки; поля состояния меняет core. Открытым может быть только один звонок. Истории и UI не входят в core. Расчёт денег, доверия, расходов, заданий, происшествий и окончания дня детерминированный. `WaveCodec` обрабатывает PCM16 WAV без UnityEngine.

Утренняя касса — OpeningCash. Поступления учитываются в Earned/Cash, покупки и платные решения — в Spent/Cash. TotalExpenses — аренда, зарплаты, CarryDebt и согласованные отложенные расходы. Касса = OpeningCash + Earned - Spent. FinalBalance = Cash - TotalExpenses. Это предотвращает двойное списание текущих покупок в отчёте.

`AdvanceTime` обновляет сотрудников и поднимает одно происшествие. При PendingEvent время и задания стоят. UI дополнительно не вызывает AdvanceTime во время обучения, чтения журнала и ожидания внешней операции. Настроение влияет на длительность работы и премию побочного обзвона.

## Runtime
`PrototypeBootstrap` пока оркестрирует UI и асинхронные реплики. У каждого клиента свои списки истории/сообщений. Смена клиента запрещена во время активного звонка, внешнего ответа или происшествия. Реплика сначала обрабатывается C#-правилами, затем необязательно перефразируется. Повторный запрос не применяется повторно к деньгам. Ревизия и CancellationToken блокируют устаревшие ответы.

`OfficeScene` создаёт из примитивов отдельный набор на расстоянии от начала сцены. Камера игрока или обзорная камера Desk рендерит на весь экран; в Desk поверх рисуется затемнённый интерфейс. Видимая геометрия — процедурные воксели (раздел «Воксельный стиль»), коллайдеры — простые примитивы. `BrokerTheme` владеет цветами, стилями и созданными текстурами. Макет 1440×960 масштабируется с letterboxing; мобильного layout нет.

`VoiceSession` сохраняет экспериментальный двухкнопочный ввод, предварительный просмотр текста, явное согласие и AudioSource. Общий синтетический голос для всех клиентов. Голосовые команды команды пока отсутствуют. Запись только по кнопке до 20 секунд, без сохранения сырого звука на диск.

## Server
Loopback Node.js, без публичного доступа/авторизации. `/dialogue` принимает boris/inna/artem и выбирает фиксированную persona на сервере. Пользовательская история вкладывается в user-данные, не становится системной ролью. Ответ ограничен JSON-полем reply. Проверка формата не гарантирует смысловой корректности модели.

`/transcribe` и `/speech` включаются отдельно через VOICE_MODE=ai. Секреты только на сервере, ограничения размеров/длительности, отмена, таймауты и лимиты запросов сохранены. Без ключа основная игра полностью локальна.

## Тестирование
`Tools/CoreChecks/CoreChecks.csproj` компилирует engine-free Core и те же NUnit-тесты, что доступны Unity Test Runner. Актуальный прогон 3 ноября (город: переход, Биржа, кофейня): 821 C#-тест на .NET 8 (676 в Assets, 145 файловых в Tools с System.Text.Json), 170 Bootstrap-flow, 16 Voice, 36 Node. Файловые тесты не импортируются Unity. GitHub Actions содержит задания core, bootstrap-flow, voice-flow, syntax, scene-preview и test.

Эти тесты не компилируют runtime против UnityEngine и не заменяют Unity PlayMode, визуальный QA, проверку разрешений микрофона, настоящий API и desktop-сборку. Пока эти проверки недоступны. Следующий технический шаг — импорт в Unity и визуальная проверка всех экранов/модалок.


## Итерация 3D: прогулка вместо постоянного dashboard

`OfficeNavigation` (Core) хранит только режим: Explore/Desk/Employee/Coffee/Upgrade/Exit/Pause. Открытие окна не тратит деньги и не завершает день. Дополнительные NUnit-тесты проверяют эти переходы и отсутствие изменения звонка.

`FirstPersonOfficeController` использует CharacterController, гравитацию и raycast до 2.7 м. Нет прыжков/тряски камеры. Компонент `OfficeInteractable` связывает предмет с разрешённой станцией, заголовком и номером сотрудника. Игрок игнорируется собственным лучом. Стол и стены имеют коллайдеры; декоративные элементы — нет.

`OfficeInput` предпочитает новый Input System при ENABLE_INPUT_SYSTEM, иначе использует legacy backend при ENABLE_LEGACY_INPUT_MANAGER. Оба не опрашиваются одновременно. Input System 1.11.2 добавлен в manifest и runtime asmdef. Настройки PlayerSettings не переписываются автоматически. Для legacy добавлены Mouse X/Y. При отсутствии ввода часы exploration не идут, доступен запасной dashboard.

`OfficeScene` создаёт перспективную камеру игрока и отдельную обзорную камеру для Desk. Они переключаются, а потолок скрывается для обзорной камеры. В мире GUI не закрывает 3D-вид большим фоном. У сотрудников воксельные фигуры с суставами шеи/плеч и процедурным движением рук, без рига/NavMesh. Сцена пока генерируется в Play Mode и не запекается в .unity.

`PrototypeBootstrap.World.cs` — partial-часть контроллера: HUD и физические станции. При закрытии окна мышь захватывается явным действием игрока. Esc из рабочего экрана отменяет внешнее ожидание/запись, но не откатывает обработанную реплику и не заканчивает звонок. Станция двери требует отдельного подтверждения.

435 C#-тестов выполнены на .NET 8, 35 Node.js-тестов — без реального API. Синтаксис всех C# проверен с четырьмя конфигурациями preprocessor. Это всё ещё не проверка Unity API, CharacterController, взаимодействий, input backend, камера/свет и визуального качества. Нужен Unity PlayMode.

## Кампания и сохранения
`CareerState` создаёт очередной `BrokerDay`, принимает только завершённый ожидаемый день и не принимает его дважды. Баланс >= 0 становится утренней кассой; отрицательный баланс превращается в CarryDebt, касса при этом нулевая. Три отчёта образуют финал; победа требует баланса >= 0 и репутации >= 40.

DTO `CareerSave` / `CareerDayReport` используют публичные сериализуемые поля, schemaVersion=1 и глубокие копии. `TryRestore` проверяет размеры массивов, диапазоны, последовательность дней и бухгалтерскую арифметику. Это защита от повреждений, не античит.

`CareerStorage` получает сериализатор через делегаты: Unity JsonUtility в runtime, System.Text.Json в файловых тестах. До замены файла проверяются сериализованные данные и лимит 64 КиБ. Запись идёт в .tmp, затем File.Replace создаёт .bak; первая запись использует File.Move. Загрузка пробует основной файл, затем резервный. При ошибке UI показывает предупреждение и позволяет повторить запись. Операции Unity JsonUtility и File.Replace на целевой ОС требуют проверки в редакторе.

`PrototypeBootstrap.Career.cs` связывает хранилище и UI. Автосохранение только после расчёта дня, либо при явном начале новой кампании. Активные звонки/задачи/аудио не сериализуются. Закрытый финал восстанавливается из отчётов; фиктивный завершённый BrokerDay нужен только для фоновой сцены и не рассчитывается повторно.


## Переговоры: детерминированный разбор и личный вопрос

`DialogueRules.Analyze` возвращает флаги `DialogueIntent`, не меняя состояние. Разбор нормализует русские фразы и разделяет их на части с сохранением десятичных чисел. Отдельные правила проверяют цель, риск, комиссию, годовой срок, персональное сопровождение, отчёт, ответ на возражение и стиль. Это не NLU и не проверка истинности обещаний; ограничения перечислены в NEGOTIATIONS.md.

`ClientConversation` хранит сценарные реплики и соответствие клиента теме возражения. `BrokerDay` единолично применяет доверие, штрафы и бонусы. `OfferDeal` сначала проверяет обязательные условия, затем поднимает вопрос; только следующий вызов после распознанного ответа и при достаточном доверии закрывает сделку. Повторный вызов после закрытия не платит. Давление и его восстановление отмечаются один раз, включая отдельный признак фактически потерянного доверия.

`ConversationStep` возвращает этап, а `NextConversationStep` формирует полную подсказку из того же состояния, что проверяет сделка, без отдельной копии правил в UI. Runtime только рисует её и меняет подпись кнопки. Новые поля `ClientRecord` не входят в CareerSave: активный день не сериализуется, схема v1 и экономика кампании не изменены. 16 тестов голосового потока остаются тестами с заменами Unity API, а не запуском Unity.


## Квартал и компактный UI

`CityBlockPlan` — детерминированные параметры 14 башен за бульваром (средние места первых двух рядов отданы Бирже). Движение машин с 3 ноября — `CityTraffic`, раздел «Город: переход, движение, Биржа». Core не знает о Unity Transform/коллайдерах. `OfficeScene.City.cs` строит площадь на y=-8, декорации и два интерактивных лифта. `Street` / `ReturnOffice` перехватываются runtime до обычной навигации: они меняют позицию, не экономику и не сохранение. Район не сериализуется. Восстановление после падения использует последнюю безопасную точку телепорта.

В офисных окнах сохранены невидимые коллайдеры при выключенном Renderer. Ограждение дороги имеет низкий бордюр, стойки, перекладину и невидимый сплошной коллайдер; в разрывах у перехода — створки, открытые только на пешеходный зелёный. Машины потока не имеют физики, столкновений, звука или управления; тестовый седан игрока ездит по кольцу на своей физике Core (раздел «Езда и кольцо дорог»). Созданные материалы освобождаются, предыдущий ambient/fog восстанавливается при уничтожении сцены.

`PrototypeBootstrap.ModernUI.cs` содержит вкладки Calls/Team/Office, карточки показателей, последнюю реплику с прокруткой, отдельные историю/досье и состояния голосовых переключателей. `BrokerPresentation` выдаёт короткие подписи по авторитетному `ConversationStage`; экономика не продублирована в UI. Ответы провайдера нормализуются префиксом имени только для экранной истории, поэтому ответ без имени и многострочный текст не теряются в компактном окне. События сохраняют исходные последствия и сатирическое описание. Схема сохранения остаётся v1.

Независимый предпросмотр исполнял runtime C# с тестовыми заменами API и переносил захваченную геометрию/GUI-команды в HTML/Three.js. Он помогает обнаружить проблемы размещения, но не проверяет настоящие Unity GUIStyle, шрифты, шейдеры, физику и компоненты. Предпросмотр — не тест Unity и не часть игры.


## Локальные текстуры
`SurfaceLibrary` строит гладкие 128×128 карты `VoxelSurfaces` (Trilinear, mipmaps, без нормалей; до 4 ноября — пиксельные 32×32, Point) и кеширует их на сцену; фото-текстуры и их загрузка из Resources удалены 3 ноября. `OfficeScene.Surfaces.cs` создаёт метрические UV и освобождает свои меши/изображения. `SurfaceMapping` в Core не зависит от Unity. Добавлен встроенный модуль imageconversion. Экономика, голос и сохранения не менялись. Подробности и ограничения: [MATERIALS.md](MATERIALS.md).


## Ежедневные дела квартала

`BrokerDay.City.cs` — partial Core с `CityWorkKind` и автоматом Available → Preparing → ReadyForPickup → Carrying → Completed. Незавершённые состояния переходят в Expired на EndDay. `AdvanceTime(seconds, inCity=false)` совместим со старыми вызовами: только runtime передаёт фактический `OfficeScene.IsInCity`. В офисе/при активном звонке подготовка стоит; PendingEvent и остальная пауза сохраняют общие правила. Награда выдаётся только после отдельного Pickup и Complete, один раз. Стоимость обедов списывается при выборе, а не при сдаче.

`OfficeNavigation` дополнен CityContact/CityPickup; эти окна не запускают часы. `OfficeScene.Activities.cs` строит интерактивное бюро и павильон вне путей телепорта; Refresh обновляет короткие вывески. `PrototypeBootstrap.City.cs` только отображает авторитетное состояние и вызывает Core. В текущем основном процессе оба окна скрыты: билдер не вызывается, обработчик взаимодействий их отбрасывает. Описанный автомат и тесты оставлены для переиспользования. Активное поручение не сериализуется; доход/расход/репутация попадают в существующий отчёт v1. Суммы укладываются в прежние ограничения валидатора сохранений. 46 новых тестовых случаев проверяют переходы, запреты, часы, повторные награды, истечение дня и восстановление трёхдневной кампании.

Текущая проверка: 385 engine-free, 16 voice-flow с заменами API, 35 серверных. Синтаксис C# 9 проверен при четырёх конфигурациях ввода; новые runtime-файлы не компилировались против настоящего UnityEngine. Предыдущую версию и локальный микрофон пользователь подтвердил как рабочие. Новая вводная глава требует Unity PlayMode; внешний API пользователь подключит позже.


## Отдельная вводная глава наёмного брокера

`CareerMode` передаётся в `BrokerDay` необязательным аргументом, по умолчанию Owner: существующие вызовы и старые тесты сохраняют поведение. `IsEmployee` запрещает поручения, покупки и городские награды в Core, не только скрывает кнопки. Аренда/зарплаты нулевые, долг/телефон при создании такого дня запрещены. События владельца и офисный бантер не запускаются. `FirmRevenue` считает полную комиссию, `Earned/Cash` — 20% личной выплаты; `FirmRetained` — остаток работодателя. Последовательность переговоров и отношения клиентов переиспользованы.

`EmploymentState` / `EmploymentSave` / `EmploymentDayReport` отделены от `CareerState`. `completedIntroDays` относится только к вводному сценарию, а не объявляет лимит всей будущей карьеры. Данные новой главы имеют собственные версию и идентификатор режима; валидатор пересчитывает комиссии по проданным клиентам, личную долю и цепочку отношений. Неполный JSON без идентификатора режима не принимается. Оба состояния отвергают дни чужого режима.

`EmploymentStorage` пишет только `broker-employee-intro-v1.json`; `CareerStorage` и прежняя схема владельца не изменены. Сериализаторы инжектируются как раньше. Меню режимов загружает выбранный файл, не сохраняет и не мигрирует другой. Смена режима во время работы требует подтверждения; при ошибке записи блокируется до успешного повтора. Новый JSON, .bak и .tmp не пересекаются со старым путём.

`PrototypeBootstrap.Employment.cs` — утро, начальник, коллеги, связь и отчёты. `OfficeScene.Employment.cs` — прототип Орлова и переключение названий/видимости предметов. Показатели начальника качественные, не новая система карьеры/повышений. Тесты Core не исполняют эти UI-ветки.

`Tools/SyntaxChecks` использует Roslyn из установленного .NET SDK (TargetFramework берётся из встроенной версии SDK, чтобы не было CS1705 при SDK 10) и только разбирает синтаксис Assets в C# 9 при четырёх комбинациях ввода. Не разрешает Unity-символы и не компилирует Unity runtime. CI добавлена такая же синтаксическая проверка; Unity build job пока отсутствует.


## Доводка вводной главы: подсказки, восстановление и flow-тесты

`RecommendedClientIndex` и `EmploymentNextAction` — чистые read-only подсказки из состояния дня. Они не выбирают контакт, не звонят, не меняют доверие или деньги. Runtime выводит блок «Дальше» с высотой по метрике текста; кнопка следующего клиента явно вызывает SelectClient и учитывает активный звонок/голос/ожидание.

Оба хранилища теперь проверяют старый основной файл перед File.Replace. Исправный основной JSON по-прежнему становится .bak. Повреждённый или неизвестной версии сначала копируется с уникальным суффиксом .unreadable-*, затем заменяется без перезаписи прежней .bak. Невозможность сохранить копию прерывает запись. Тесты проверяют повторное повреждение после восстановления и сохранение байтов будущей версии. Реальные File.Replace/JsonUtility на Windows всё ещё требуют ручного запуска.

`Tools/FlowChecks` компилирует реальные Core/Bootstrap/Voice/Dialogue и OfficeInteractable с узкими тестовыми заменами UnityEngine, OfficeScene, player и BrokerTheme. Подставной GUI потребляет одну кнопку по тексту, JSON использует System.Text.Json. 80 случаев проверяют контроллер: часы в меню/окнах, расчёт дня один раз, возврат финала, изоляцию сброса, повтор записи, защиту переноса/повтор загрузки, подтверждение завершения звонка и независимые сигналы focus/pause с явным возвратом к столу. Это не сборка сцены и не проверка графики, геометрии, реального GUI, input backend или Unity JsonUtility. Подробности: [Tools/FlowChecks/README.md](../Tools/FlowChecks/README.md).

## Повторяемый режим employee-work

`CareerMode.EmployeeWork` — отдельный наёмный режим. `IsEmployee` включает строго Employee/EmployeeWork; `IsRepeatingWork` отличает продолжение. `EmploymentState` принимает Employee, `CareerState` — Owner, `WorkCareerState` — EmployeeWork, `FirmCareerState` — Founder. Два повторяемых режима допускают номера 4+ с каноническими `clientIds`; старые лимиты/расписания владельца и вступления не расширяются.

`ClientCatalog` задаёт шесть стабильных ID, параметры/специальные требования и четырёхдневный цикл по три контакта. Начальное доверие/возврат извлекаются по ID, тогда как GUI/истории остаются на три дневных слота и очищаются при Restart. Новые реплики и AnswerIntent в ClientConversation авторские; словарный движок не превратился в семантический ИИ. Шлюз принимает все шесть фиксированных персон.

`WorkCareerSave` хранит schemaVersion=5/mode=employee-work, stockHistoryFromDay, marketFromDay, portfolioFromDay, исходный перенос origin, checkpoint и до семи WorkDayReport. Контрольная точка содержит личные деньги/репутацию, отношения, число рабочих сделок, awaitingReport и портфель каждого клиента. При восьмом отчёте старейший сворачивается в checkpoint; последние отчёты переигрываются валидатором, проверяются порядок расписания, суммы и перенос. Финансовая целостность checkpoint точно сопоставляется со стартовыми накоплениями и личными выплатами каждого клиента по ставкам: число сделок, из них по 3% (`dealsAt3`) и 5% (`dealsAt5`); остальные — 2%. Формат проверяет целостность, не является защитой от намеренного редактирования. Поля Int32 сохраняют технические пределы, но больше нет сценарного финала DayNumber==3 в этом режиме.

`awaitingReport` переносится через дни отсутствия клиента; только обсуждённый отчёт снимает старый запрос, новая продажа создаёт новый. Отношение меняется по `StockPortfolio.RelationshipChange` (sold/closed/гарантия/претензия/падение цены); отсутствие звонка нейтрально, кроме дня падения портфеля (−1). `origin` позволяет сбросить продолжение к первоначальному переносу даже после сворачивания истории или сброса вступления.

`WorkCareerStorage` использует отдельный broker-employee-work-v5.json с теми же безопасными .bak/.tmp/.unreadable-* правилами. Начальный переход сначала должен успешно записать новый файл; без этого меню подтверждения остаётся открытым. `PrototypeBootstrap.Work.cs` содержит явный перенос и итоги; новое продолжение не перезаписывает существующее при повторном выборе из финала вступления. Unity/Windows-проверка обязательна: [WORK_DAYS.md](WORK_DAYS.md).

Перегрузка `TryLoad` возвращает `WorkCareerLoadStatus` (Missing/Loaded/Unreadable): runtime не выводит решение о новом переносе из текста уведомления. Ошибки чтения/доступа и каталоги не считаются отсутствием. `TryCreate` применяется только к первому переносу: проверяет отсутствие продолжения после сериализации, использует собственный `.tmp-*` и `File.Move` без замены основного файла. Обычный `TrySave` сохраняет прежние правила записи/восстановления. Подтверждение заново читает продолжение; исправный появившийся файл загружается без записи, нечитаемый блокирует перенос. Меню разрешает повтор загрузки независимо от завершённости вступления. Это не протокол синхронизации одновременных запусков игры.


## Претензии к гарантиям (employee-work)

`ClientRecord` хранит флаги исходной претензии, признания ошибки, объяснения риска, урегулирования и сегодняшней ложной гарантии. `DialogueIntent.AdmitError` — отдельный детерминированный флаг. `ConversationStage.Complaint` стоит перед отчётом/условиями; `OfferDeal` повторно проверяет блокировку, а не доверяет только UI. Гарантия обрабатывается до прочих фактов сообщения; её нельзя спрятать за признанием ошибки в той же реплике. Новый promise в звонке со старой претензией не позволяет заново получить бонус урегулирования.

`WorkDayReport.guaranteed/complaintResolved` — массивы трёх дневных слотов. `WorkClientState.complaintPending` — постоянный флаг по ID. Apply проверяет размеры и совместимость флагов: урегулировать можно только существующую претензию, без новой гарантии; продажа при неурегулированной старой претензии недопустима. Уходящий за окно отчёт переносит претензию в checkpoint. Все readback-массивы глубоко копируются.

`TryRestore` принимает v5, v4, v3, v2 и валидный v1; старые цепочкой v1→v2→v3→v4→v5 нормализует в новый объект, не меняя вход (v1 — с пустыми полями претензий, v1/v2 — с пустыми бумагами и stockHistoryFromDay = следующий день, v1–v3 — без цен, с нулевыми счётчиками ставок и marketFromDay = следующий день, v1–v4 — с портфелем из последней покупки с ценой (`FromLastPurchase`, у v1–v3 пустым), пустыми `concernResolved` и portfolioFromDay = следующий день). Перед каждым шагом структура проверяется до копирования: v3 с ценами, счётчиками или marketFromDay отклоняется, v4 с портфелями, `concernResolved` или portfolioFromDay — тоже (`LegacyPortfolioFieldsEmpty`), а точная проверка денег не принимает старые сделки выше 2%. `WorkCareerStorage` в runtime получает read-only `params` пути старых поколений, новейшее первым (v4, v3, v2, v1): каждое со своей .bak, файл поколения принимает свою и более старые схемы и используется только при полном отсутствии файлов новее. Декодирование неизвестной версии не разрешает молчаливый откат. Файлы v1 и `.bak` не перезаписываются. Проверки сериализации на Linux используют System.Text.Json, не Unity JsonUtility.

## Founder — основание и первый помощник

`CareerMode.Founder` добавлен в конец enum, не меняет номера прежних режимов. `IsRepeatableCareer` объединяет Work/Founder для сохраняемых гарантий. Founder получает полную комиссию, аренду $60 и зарплату $40 только при `HasFounderAssistant`. Два EmployeeRecord остаются совместимыми данными сцены; после найма доступен только индекс 0/Research, 25 секунд независимо от настроения. Leads/Break/покупки/городские награды запрещены в Core. Досье даёт +1 доверия раз клиенту/день, не раскрывает условия и не продаёт; активные задачи не сериализуются. События/бантер и городские активности запускаются строго в Owner.

`FirmCareerState.FromWork` копирует только завершённое состояние с $600+. `FirmCareerSave` schemaVersion=5/mode=founder содержит stockHistoryFromDay/marketFromDay/portfolioFromDay/sourceDay/sourceSavings/personalReserve/assistantHireDay, origin/checkpoint и семь FirmDayReport с salary. Резерв = sourceSavings − $200 − $300 и не меняется. `assistantHireDay=0` означает отсутствие найма; иначе найм за $100 перед указанным днём. Баланс checkpoint = $300 + полные комиссии по ставкам (2% + счётчики 3%/5%) − $60 × completedDays − $40 × дни после найма − $100, если день найма уже завершён. Pending найм вычитается из публичного Balance до первого дня, но не меняет старую контрольную точку/отчёты. Apply проверяет первый openingBalance с расходом найма, порог кассы $200, последующие зарплаты, расписание и флаги. Исходные сделки/последнее появление обнуляются для локальной истории фирмы; обязательства сохраняются. Номер дня не обнуляется. TryRestore принимает валидный v1 без сотрудника/зарплаты, v2, v3 и v4 и нормализует защитную копию в v5.

Утро использует max(0, balance) и CarryDebt=max(0, −balance). FinalBalance учитывает долг один раз, новую аренду и зарплату; CompleteDay принимает только ожидаемый завершённый Founder с совпадающим наймом, без покупок/посторонних выплат. TryHireAssistant создаёт отдельный кандидат без изменения исходника; runtime активирует его только после записи. Сброс через RestartFromOrigin возвращает открытие без найма независимо от изменённого Work. Все DTO глубоко копируются. Проверка целостности не античит; Int32 имеет технические пределы.

`FirmCareerStorage` пишет только broker-founder-v5.json с инжектированными сериализаторами и лимитом 64 КиБ. Пути старых поколений (v4, v3, v2, v1; каждый принимает только свою схему) read-only: поколение с .bak читается только при полном отсутствии файлов новее, никогда при повреждённом новом файле. Missing/Loaded/Unreadable различаются явно, каталоги/ошибки доступа блокируют создание. TryCreate после сериализации проверяет отсутствие всех файлов. Данные после сериализации должны совпадать со снимком (`SameSnapshot`), включая hireDay/salary, marketFromDay, цены, portfolioFromDay, портфели и concernResolved. TryHireAssistant перечитывает и сравнивает ожидаемый сохранённый снимок перед записью; ошибка не активирует кандидат. Уникальный `.tmp-*`, File.Move для создания, File.Replace с `.bak` для здорового файла и `.unreadable-*` без замены здоровой `.bak` для повреждённого. Это не конкурентный протокол/блокировка нескольких запусков.

`PrototypeBootstrap.Firm.cs` содержит карьерный экран, подтверждение, утро/итоги и страницы конторы/связи. Открытие/продолжение из карьерного экрана разрешено только утром/в итогах после успешной записи; меню может продолжить уже существующую контору независимо от вступления. Подтверждение заново читает founder-файлы, не заменяет появившееся сохранение. Career/Settings/Bootstrap маршрутизируют расчёт/сброс/часы, WorkNotebook использует источник соответствующей ветки. Нельзя переводить деньги через меню независимых снимков.

`OfficeScene.ConfigureCareerMode(mode, founderAssistant)` показывает Лену после найма, скрывает Макса/Орлова/витрину и исключает кофемашину из луча; при смене режима возвращает прежнее окружение. Runtime блокирует остальные станции. Найм доступен в Firm-утре/итогах, досье — в странице конторы за столом или отдельной физической панели. Мебель переиспользована; scene-файлы не запекаются. Реальное поведение Unity API, raycast/видимости и компоновка не покрыты headless-тестами. Пользователь подтвердил предыдущую версию, но не эту сцену; чек-лист [FOUNDER.md](FOUNDER.md).

Доводка помощника: `TryHireAssistant` сверяет именно основной v5 после сериализации, не принимает совпавший резервный снимок как разрешение замены повреждённого/пропавшего основного файла. После восстановления из v5/.bak нужен восстановленный основной файл либо успешная запись завершённого дня. Отдельный read-only v4, v3, v2 или v1/.bak при полном отсутствии v5 сохраняет прежнее поведение. `BrokerDay.CloseCurrentCall` используется ручным завершением, продажей и гарантией с нулевым доверием: в Founder отменяет только незавершённое Research текущего клиента и уведомляет без бонуса. Owner не меняется. `DossierStatus`/`AssistantWorkStatus` только отображают состояние в панелях и карточке. Таймер досье по-прежнему обновляется до автоматического конца дня; точные 25 оставшихся секунд дают готовность, меньший остаток не даёт бонуса.

## Визуальная база полной версии

Расширение района: `CityDistrictPlan` описывает пешеходную область обоих кварталов, непроходимые фасады с проёмами (кофейня, зал Биржи), высоты пола (север +0,12 м, лестница, подиум +1,1 м) и восемь immutable ориентиров, считает расстояние по прямой/направление («через переход» для другой стороны бульвара). `OfficeScene.City/District` строит соединённые полы, периметр, шесть ближних фасадов, уличные объекты/стенды; Визуал с 3 ноября — воксельные генераторы (`PlaceVoxel`, раздел «Воксельный стиль»); прежний загрузчик OBJ `PlaceLocalModel` удалён. `PrototypeBootstrap.CityMap` добавляет карту/стенд компаний и day-local waypoint, а новые станции/виды добавлены в конец enum. Карта/стенд останавливают время; карта из паузы возвращается в паузу, не теряет desk-return. Стенд ничего не продаёт/не раскрывает клиенту. Движение машин остаётся визуальным за барьером, экономика/save не меняются. [Правила и QA](CITY_DISTRICT.md).

Каталог акций — отдельные правила Core, не часть геометрии/материалов. `StockCatalog` содержит шесть immutable предложений и профили допустимого риска/горизонта клиентов. `ClientRecord.StockId`/`StockRiskExplained` относятся только к текущему дню. `BrokerDay.Stocks` меняет выбранную акцию до принятого предложения, сбрасывает только раскрытие её риска/комиссии; явное `ExplainStockTerms` раскрывает выбранные свойства без денег/доверия. `OfferDeal` проверяет соответствие и подробный риск для спекулятивных бумаг, затем прежние условия/обязательства/вопрос. С v3 ID проданной бумаги сохраняется в истории рабочих дней и конторы; с v4 там же цена покупки, а ставка комиссии зависит от риска (см. ниже); с v5 — портфель клиента (см. ниже). `PrototypeBootstrap.Stocks` — модальное окно с паузой/черновиком и защитой focus/voice/busy; у сервера удалена жёсткая подсказка одного безымянного продукта, он по-прежнему только перефразирует canonicalReply. [Правила/пределы](STOCKS.md).

История акций v3: `WorkDayReport.soldStockIds` и `FirmDayReport.soldStockIds` хранят ID бумаги по дневному слоту (пустая строка без сделки), клиенты checkpoint — `lastStockId/lastStockDay`, сохранение — `stockHistoryFromDay`. `CompleteDay` берёт ID из `ClientRecord.StockId` проданного клиента. Валидатор (`WorkCareerState.ValidStockRecord`) требует бумагу только у сделки, подходящую профилю клиента, и у каждой сделки начиная с `stockHistoryFromDay`; последняя покупка сверяется с переигранными отчётами и переживает свёртку. `FirmCareerState.FromWork` переносит последнюю покупку как покупку «ещё в найме», сброс конторы ведёт историю с sourceDay. `StockHistory` — чистые функции показа (Investment/Short/Describe/SoldToday/LastPurchase): вложение и комиссия выводятся из каталога клиентов и 2%, неизвестный/пустой ID показывается как «до истории акций», тикер не угадывается. Owner/intro и их файлы не изменены.

Котировки и ставки v4: `StockMarket` — чистая целочисленная функция цены (бумага, абсолютный день): базовая цена × (1 + две треугольные волны + шум SplitMix64 от дня) в базисных пунктах, с публикуемым коридором Min/MaxPriceCents; одинаково на любых платформах, без реальных данных и сохранённого состояния рынка. Ставка — свойство `StockOffer.FeePercent` по риску (2/3/5%); `BrokerDay.HasQuotes` = `IsRepeatableCareer`, поэтому intro/owner сохраняют `StockCatalog.FeePercent` = 2% и прежние тексты. `BrokerDay` передаёт ставку выбранной бумаги в `DialogueRules.Analyze(message, feePercent)`, подсказки и `ClientConversation.Fee`; комиссия = `StockMarket.Commission`, число акций — целое `Investment × 100 / цена`. При продаже `ClientRecord.SoldPriceCents` = котировка дня; `CompleteDay` пишет `soldPrices`, `lastStockPrice` и увеличивает `dealsAt3/dealsAt5`. Валидатор требует цену = котировке дня сделки (с `marketFromDay`, раньше 0), ставку только из допустимых клиенту (`CanPay`), счётчики не больше сделок и рыночных дней, и точную сумму денег. `ReportQuoteNote`/`StockHistory.TodayQuote` только показывают сравнение цены покупки и сегодняшней. Шлюз получает правило называть только числа из canonicalReply.

Портфели v5 (`StockPortfolio.cs`, `BrokerDay.Portfolio.cs`): `StockPosition` {stockId, day, priceCents} — покупка с ценой, число акций выводится `StockMarket.Shares`. `WorkClientState.portfolio` — до трёх последних позиций по возрастанию дня (`StockPortfolio.Add` вытесняет старейшую), `CompleteDay` добавляет проданную бумагу по `SoldPriceCents`. `CreateDay` вызывает `BrokerDay.AttachPortfolio` один раз до первого звонка: `ChangeTenths` (целые десятые процента, округление к нулю) и `Mood` (Growth ≥ +50, Drop ≤ −50, DeepDrop ≤ −150) фиксируются в `ClientRecord` на день; Growth +1 доверия, DeepDrop −1. `ConversationStage.PriceConcern` стоит после Complaint и до Report; `Risk` без открытой претензии и без ложной гарантии ставит `PriceConcernResolved`. `DialogueRules` выделяет `DialogueIntent.Rebound` (`RecoveryPromise`: «точно/обязательно … вырастет/вернётся», «цена … отыграется»; отрицания, «может», вопросы и «не могу обещать» отсекаются, текст после «но/однако/зато» проверяется отдельно); при `HasQuotes` это та же ложная гарантия. `OfferDeal` блокирует сделку до объяснения, `FitsToday` после DeepDrop пропускает только Moderate. Отчёт дня хранит `concernResolved`, сохранение — `portfolioFromDay`. Валидатор переигрывает настроение каждого слота от `origin`: `ValidReaction` (флаг только в день падения, в закрытом звонке без гарантии; сделка — после объяснения; после DeepDrop — умеренная бумага), `RelationshipChange` (к v4: 0 вместо −1 за честно объяснённое падение без сделки, −1 за падение без звонка) и `StockPortfolio.Valid` для checkpoint (канонические цены своего дня, строгий порядок, последняя позиция = последняя покупка, свои позиции не больше сделок и счётчиков 3%/5%; в founder позиции до `sourceDay` — из найма). `PortfolioBadge`, `PriceReactionsSummary`, `StockSuitability`, `StockPortfolio.Describe` — только показ (список звонков, карточка, чип «Цена», каталог, блокнот, итоги). Owner/intro портфелей не получают.

`OfficeScene.Models.cs` с 3 ноября ставит воксельную мебель (`BuildVoxelFurniture`) вместо OBJ из Resources. Мебель не содержит игровых станций/коллайдеров: исходные простые коллайдеры остаются, скрывается только Renderer заменённых конструкций. Мониторы/телефон/персонажи сохраняют прежние визуалы, включая процедурную анимацию/смену экранов; авторские модели потребуют отдельного подключения.

Прежние CC0-модели/текстуры, их реестры `ThirdParty/` и скрипты `Tools/Art/` удалены 3 ноября: сцена воксельная и не загружает ресурсов. Сцену всё ещё создаём при Play, не вводим сериализованные prefab/.unity ссылки. Следующие этапы: [PRODUCTION_ROADMAP.md](PRODUCTION_ROADMAP.md), задания/ручная проверка — [ART_BRIEF.md](ART_BRIEF.md).

## Воксельный стиль

Core без движка: `VoxelPalette` — 63 цвета в текстуре 8×8, индексы 56–63 светятся. `VoxelModel` — сетка индексов палитры (X вправо, Y вверх, модель смотрит в −Z, pivot — низ по центру); `VoxelNoise` — целочисленный хеш, одинаковый на всех платформах. `VoxelMesher` выводит только грани на границе с пустотой, считает затенение каждого угла грани по трём соседним вокселям (`VoxelMesh.Shades`) и сливает соседние грани в прямоугольники при равных цвете и затенении; светящиеся грани — отдельный submesh. `ScreenLook` и `SkyLook` — общие для шейдеров и предпросмотра параметры экрана (bloom, SSAO, грейд, виньетка, свечение дымки, sRGB) и неба (палитра, солнце, облака). `VoxelProps` — генераторы природы, улицы, людей (`VoxelFigure`: тело, голова, руки, точки шеи/плеч), мебели, башен по `CityBlockPlan`, магазинов и стендов. `VoxelSurfaces` — гладкие бесшовные рисунки 128×128 по ключу поверхности. Машины не воксельные: `PolyMesh` — low-poly меш по частям (вершины, нормали, UV, треугольники части), `CarModels` — пять кузовов (`CarStyle`: седан, такси, хэтчбек, пикап, фургон; лофт по сечениям из `BodyPlan`, детали в `CarModels.Bodies.cs`), колесо по размеру кузова, размеры `CarShape` (`Shape(style)`, у такси — седана), краски и зерно краски. Здания с этапа 2 графики тоже не воксельные: `BuildingModels` на том же `PolyBuilder` — башни (`Tower`, три стиля, этажи `Floors`), дома улиц (`Shop`), кофейня с открытым залом (`Cafe`), вид стены `WallLook`; части `BuildingPart` — стены, детали, стекло, ночное стекло (окна, которые горят после заката, этап 4); детали фасада — в `BuildingModels.Facades.cs`. `StreetModels` (partial) на том же `PolyBuilder` — живая изгородь, с этапа 3 деревья пяти видов с оттенком листвы `TreeLook`, ели, кусты, кадки и газоны (`StreetModels.Green.cs`), фонарь, скамейки и урна (`StreetModels.Furniture.cs`), с этапа 3б столб светофора, автомобильная и пешеходная секции с вариантами горящей лампы и кнопка перехода с константами подвеса секций на столбе (`StreetModels.Crossing.cs`), столбик, конус, ограждение работ и мусорный контейнер (`StreetModels.Works.cs`), стенды площади `InfoStand(style)` со свободной полосой для надписи (`StreetModels.Stands.cs`); формы — `PolyShapes` (тела вращения, эллипсоиды, неровные комки листвы `Lump`, трубки `Limb` и `Sweep`, блоки). `PeopleModels` (этап 5, partial) на том же `PolyBuilder` — прохожие `Walker(style)` и сотрудники `Staff(style)` → `PersonModel` (торс, голова, руки, ноги, сидячие ноги и рука на столе, суставы, `PitchToReach`); сотрудники строятся детальнее (`Outfit.Fine`: больше сторон, сглаженный торс, пальцы, пряди); тело и одежда — в `PeopleModels.Body.cs`, голова, причёски, головные уборы и накладка лица `Face(mood, brows)` (глаза, брови, рот; `FaceMood`) — в `PeopleModels.Head.cs`. `CityScenery` — расстановка района и дальней застройки, константы тумана и дальности. `DayCycle` (этап 4) — часы рабочего дня (9:00 → 00:00, 40 с на час; `HourOf(day)` — для HUD и света сцены) и свет любого часа (`At` → `DayLight`: направление, цвет и сила солнца или луны, окружение, дымка, палитра неба, доля ночных огней) из настроений в ключевые часы, плавно между ними; яркий день и золотой час — значения PR #12 и PR #8.

Runtime: `OfficeScene.Voxels.cs` строит Unity Mesh один раз на ключ модели и держит два материала на шейдере `Broker/Voxel` (текстура палитры Point, затенение углов из цвета вершин; светящийся — тусклый albedo и emission; без шейдера — Standard). `PlaceVoxel` ставит модель; с этапа 5 люди low-poly — `OfficeScene.People.cs` (`PlacePerson`) собирает человека из частей `PersonModel` через `PlaceBuilding` для прежней процедурной анимации, лицо — отдельный объект на голове, выражение всех лиц `Mood` (по умолчанию `Calm`) — в Inspector'е; `OfficeScene.Cars.cs` (`PlaceCar`) собирает машину из кузова и четырёх колёс с материалами краски, стекла, фар и стоп-сигналов, `PoseCar` крутит колёса и переключает стоп-сигналы; `OfficeScene.Buildings.cs` (`PlaceBuilding`) строит меш здания один раз на ключ и даёт ему материалы стен по `WallLook`, деталей по палитре, стекла, ночного стекла, свечения (светящийся материал вокселей) и металла (палитра, металличность 0.6), без коллайдеров, по запросу без теней (дальняя застройка); с этапа 2б так же ставятся Биржа с площадью (`BuildingModels.Exchange.cs`), киоск, порталы тоннелей, дальняя застройка (`BuildingModels.Street.cs`) и живая изгородь (`StreetModels`), с этапа 3 — деревья, ели, кусты, кадки, газоны (`StreetModels.Green.cs`), фонари, скамейки и урны (`StreetModels.Furniture.cs`), с этапа 3б — светофоры с кнопкой (`OfficeScene.Boulevard`: `BuildSignals`, варианты ламп — `SignalVariants`), столбики, конусы, ограждение, контейнеры и стенды (`OfficeScene.District`); `PolyToMesh` общий у зданий и машин; всё созданное освобождается в OnDestroy. Воксели не получают станций и коллайдеров, кроме небольших коллайдеров стволов/столбов в проходимой части; у прежних примитивов скрывается только Renderer. `OfficeScene.Atmosphere.cs` задаёт солнце, трёхцветное окружение, линейный туман цвета `SkyLook.Haze`, небо `Broker/Sky` по `SkyLook` (без шейдера — копию процедурного неба) и дальность теней, сохраняя прежние значения и восстанавливая их при уничтожении сцены. `OfficeScene.DayNight.cs` (этап 4) каждый `Refresh` ставит свет часа рабочего дня (`FollowDay`, `SetHour`; `HourOverride` — для проверки): солнце или луну, окружение, туман, палитру неба, раз в 3 минуты городских часов — отражения (`DynamicGI.UpdateEnvironment`); после заката — ночное стекло, плафоны и свет 25 фонарей (`PlaceStreetLamp`), свет над дверью офиса, ярче фары и лампы комнат. `CameraPost` на камерах глаз — пост `Hidden/Broker/Post` через `OnRenderImage`: SSAO, свечение солнца в дымке, bloom, ACES и грейд, виньетка, дизеринг; без шейдера или half-float выключается. `PrototypeBootstrap.World.cs` рисует HUD без панелей: текст с тенью (`HudLabel`), в центре — время города (с этапа 4 вместо отсчёта; так же на рабочем экране), полоса денег, клавиша E с названием цели и крестик-прицел.

`Tools/ScenePreview` компилирует Core, `OfficeScene*.cs`, `SurfaceLibrary` и `OfficeInteractable` в C# 9 против узких заменителей UnityEngine и программно рендерит кадры тем же путём, что Unity в Linear и HDR: Standard BRDF, затенение вершин, небо `Broker/Sky`, каскадные тени, туман, пост `CameraPost` (SSAO, свечение дымки, bloom, ACES). `--check` используется в CI. Это не Unity-рендер. Подробности: [VOXEL_STYLE.md](VOXEL_STYLE.md), [Tools/ScenePreview/README.md](../Tools/ScenePreview/README.md).

## Город: переход, движение, Биржа

Core без движка, детерминированно на всех платформах:

- `CrosswalkSignal` (`CityCrosswalk.cs`) — автомат фаз CarsGo → CarsAmber → ClearToWalk → Walk → WalkEnding → ClearToCars, 14/3/1/10/4/2 с. `RequestWalk` сокращает зелёный машинам до 6 с от начала фазы и сбрасывается на жёлтом. Удержания: ClearToWalk ждёт, пока машина в зоне перехода уедет, ClearToCars — пока зебра опустеет. `CityCrosswalk` — геометрия зебры и стоп-линий, `PlayerInZone`, `GatesOpen` (зелёный пешеходам или игрок уже на зебре), `Near`, текст `Hint`.
- `CityTraffic` — 12 машин (`CityCar`) на кольце 180 м: x −90…90, концы спрятаны в тоннелях. Четыре полосы по три машины, круиз 6,4–7,5 м/с, разгон 2 м/с², торможение 3 (максимум 6) м/с², дистанция до соседа по длинам обеих машин. Кузова идут в постоянном порядке: 4 седана, 3 хэтчбека, 2 такси, 2 пикапа и фургон; `CityCar.Shape`, `Length`, `Width` и `Footprint` (прямоугольник кузова для машины игрока) берутся из `CarModels.Shape(style)`. `Braking` — стоп-сигналы (замедление от 0,8 м/с² или стоянка), `Paint` — цвет из `CarModels`. На красный машина стоит у стоп-линии; на жёлтый останавливается, если успевает жёстким торможением, иначе проезжает, и сигнал её ждёт. Люди на зебре держат машины. `CarInCrosswalk` — для удержания сигнала.
- `CityCrowd` — семь замкнутых маршрутов (`CityRoute`), 14 прохожих (`CityWalker`) и четыре фигуры на местах (`CityFigure`). Отрезок маршрута от бордюра до бордюра — зебра: прохожий ждёт зелёного и начинает, только если успевает дойти. Остановка перед игроком за 1,2 м, следование друг за другом, уступка прохожему другого маршрута; через 2,5 с ожидания проходит, поэтому пересекающиеся маршруты не запираются.
- `CityLife` — общие часы бульвара шагом 0,05 с: сигнал → машины → прохожие → машина игрока (`Car`). Игрок на зебре удерживает сигнал как прохожий. Длинный кадр даёт ту же картину, что много коротких.
- `ExchangeBoard`/`ExchangeQuote` (`CityInformation.cs`) — строки табло из `StockMarket` только при `BrokerDay.HasQuotes`, иначе пусто и «ТОРГИ ЗАКРЫТЫ». `CityChatter` — 15 реплик, три разные на номер дня.
- `VoxelProps.City` — генераторы прохожих из частей (`VoxelWalker`), Биржи, площади, кофейни, светофоров, кнопки, портала тоннеля, изгороди и газона. С этапа 2б Биржу, её площадь, киоск, портал и изгородь, с этапа 3 и газоны, с этапа 3б светофоры и кнопку, с этапа 5 прохожих сцена ставит low-poly (`BuildingModels.Exchange`, `BuildingModels.Street`, `StreetModels`, `PeopleModels`) в тех же размерах и pivot'ах; воксельные генераторы остаются в коде и тестах. `CityScenery` расставляет их и мебель кофейни.

Runtime:

- `OfficeScene.Boulevard` — полосы, бордюры, ограждение, створки, светофоры с кнопкой и отсчётом, тоннели; машины `OfficeScene.Cars` по позициям, пройденному пути и торможению из `CityTraffic`; меш кузова — один на стиль, колёс — один на `CarShape`. `OfficeScene.Exchange` — low-poly подиум, плитка, паркет, зал, крыша, статуи и табло, лестница-рампа для CharacterController, коллайдеры стен зала, тексты табло (TextMesh меняется только при смене дня). `OfficeScene.Cafe` — low-poly корпус (`BuildingModels.Cafe`), стены у входа, свет, вывеска. `OfficeScene.Crowd` — прохожие и фигуры из частей (`PlacePerson`), шаг ног и рук.
- `OfficeScene.City` держит `CityLife`; `AdvanceCity` вызывается каждый кадр (не больше 0,1 с), только пока `WorldMotionEnabled`. Bootstrap выключает его вместе с рабочими часами: окна карты, стенда, табло и кофейни, пауза и потеря фокуса останавливают и день, и город. `RequestCrossing` и `CrossingHint` — для кнопки и HUD. Изгороди на концах улиц — простые коллайдеры с воксельной изгородью.
- `PrototypeBootstrap.World`: `IsStreetStation` — станции улицы работают только в городе; кнопка перехода действует в мире и не открывает окна. HUD ориентира и строки «ПЕРЕХОД / СВЕТОФОР». `PrototypeBootstrap.CityQuarter` — окна табло и кофейни, `PrototypeBootstrap.CityMap` — схема с девятью ориентирами, кольцом и парковкой. Новые станции/виды (`CityExchange`, `CityCafe`, `CrosswalkButton`) — в конце enum.

Город не сериализуется и не меняет экономику: табло и кофейня только показывают, прохожие — не клиенты, машины потока без физики. Тесты: `CityTrafficTests`, `CarModelTests`, `PeopleModelTests`, `CityCrowdTests`, `CityInformationTests`, `CityDistrictTests` (Core), `BootstrapCityQuarterFlowTests` (Flow). Правила и QA: [CITY_DISTRICT.md](CITY_DISTRICT.md).

## Езда и кольцо дорог

Core без движка, детерминированно:

- `OrientedRect` — повёрнутый прямоугольник (центр, курс, половины длины и ширины): точка внутри с запасом, расстояние снаружи, пересечение по разделяющим осям, углы и габарит.
- `CityRoads` — кольцо в координатах `CityDistrictPlan`: бульвар между бордюрами до порталов тоннелей, западная, южная и восточная улицы, карман `Bay` у западного сквера и зона парковки `ParkingZone`, срезы углов бордюров под 45° (`KerbCuts`). `Ring` — `DriveArea` (объединение прямоугольников с найденными внутренними углами бордюров), `Frontage` — 12 башен вдоль внешней стороны, `Lamps` — 11 фонарей, `Solids` — дома для камеры, `ClearFraction` — какая доля отрезка от машины до камеры свободна.
- `PlayerCar` — тестовый седан: одноколейная модель с переносом нагрузки, кругом трения шин, четырёхступенчатым автоматом, тормозами, ручником и помощником устойчивости, шаг 1/200 с. Бордюры `DriveArea`, машины `CityTraffic` и прохожие `CityCrowd` — твёрдые препятствия: удар с отскоком без повреждений, перед людьми помощник тормозит. `Parked` — стоит в кармане; `Park`/`Place`/`Stop`; `Footprint`, `Kmh`, `GearLabel`, крен и тангаж для вида. `DriveInput` — газ/тормоз, руль, ручник.
- `CityLife.Car`, `Driving`, `Input`: `EnterCar`, `LeaveCar` (только при `Parked`), `ParkCar`. Футпринт машины передаётся потоку (`CityTraffic.Advance(…, obstacle, velocityX)` — лидер для каждой полосы, в которую он заходит) и прохожим (`CityCrowd.Advance(…, car)` — стоят перед кузовом); машина на зебре держит пешеходный зелёный, как машина потока за стоп-линией.

Runtime:

- `OfficeScene.Roads` — асфальт улиц и кармана, срезы-призмы, бордюры, тротуары, разметка, фонари, башни `Frontage`, ограждение кармана с барьерами и двусторонним знаком «P / ПАРКОВКА». Стены кольца держат только пешехода; машину останавливает Core.
- `OfficeScene.Driving` — седан из `OfficeScene.Cars` с BoxCollider и `OfficeInteractable` («Сесть за руль») для прицела; `EnterCar`, `TryLeaveCar` (игрок встаёт у кармана), `ParkPlayerCar`; каждый кадр — поза, крен, поворот передних колёс; `ChaseCamera` — камера сзади с запаздыванием по курсу, вращением мышью и `ClearFraction` против стен.
- `FirstPersonOfficeController`: `Seat`/`Unseat`, `Seated`, `Drive` (W/S, A/D, Space через `OfficeInput.Handbrake`), `OrbitYaw`/`OrbitPitch`, E за рулём — `OnLeaveRequest`. Bootstrap: станция `Car` в конце enum, выход только на парковке, HUD езды (`DrawSpeedometer`, `DrawLeaveCarLine`, клавиши первые 10 с), вариант паузы и карты за рулём.

Езда не сериализуется и не меняет экономику: рабочее время идёт как на прогулке, денег и бонусов нет. Тесты: `PlayerCarTests`, `CityRoadsTests`, `CityDrivingTests` (Core), `BootstrapDrivingFlowTests` (Flow). Правила и QA: [CITY_DISTRICT.md](CITY_DISTRICT.md).
