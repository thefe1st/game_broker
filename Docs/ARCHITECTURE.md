# Архитектура

## Сейчас
`Broker.Core` — чистые правила C#, без UnityEngine. `Broker.Runtime` — временный IMGUI и таймер. `Broker.Editor` создаёт сцену. `Broker.Tests` содержит EditMode-тесты. Runtime bootstrap создаёт интерфейс после загрузки сцены, если его ещё нет. Scene menu создаёт пустую стартовую сцену; сцену не требуется собирать вручную.

## Следующая итерация (ещё не реализована)
Ввести IDialogueProvider, ISpeechToTextProvider, ITextToSpeechProvider и отдельный CallController. Асинхронные операции с CancellationToken, ограничением времени и запретом параллельной отправки реплик. Не переносить текущие лексические правила в оценку ИИ-разговора без переработки: нужна отдельная проверка смысла и условий сделки.

Unity → HTTPS-шлюз → внешний провайдер. Ключи только на сервере. Шлюз проверяет размер запросов, идентификаторы, схему ответа и лимиты. Клиентская реплика — недоверенные данные, не системная инструкция. Пригодность продукта, изменение доверия и расчёт денег — ответственность игровых правил, не произвольного текста модели. Текущая логика упрощена для одного сценария.

Сохранять только необходимые факты разговора. Не писать сырой звук в логи по умолчанию. Перед включением голосового ввода показать понятное уведомление об обработке речи. Реальные провайдеры и бюджет пока не выбраны.

## Проверка
Тесты добавлены, но ещё не запущены в Unity. Нужны проверка импорта пакетов, запуск сцены, кириллицы, поведения при изменении размера окна и desktop-сборки. После первого импорта закоммитить Unity .meta и Packages/packages-lock.json.


## Итерация 2: шлюз и отмена
Реализованы `IDialogueProvider`, `OfflineDialogueProvider`, `LocalGatewayDialogueProvider`. Последний использует UnityWebRequest, таймаут 12 секунд и CancellationToken. UI запрещает параллельную отправку; идентификатор ревизии блокирует поздние ответы после сброса. Пока оркестрация находится в PrototypeBootstrap; отдельный CallController ещё не выделен.

Локальные правила применяются один раз перед вызовом провайдера. Шлюз перефразирует канонический ответ, но не классифицирует смысл игрока и не решает сделку. Ошибка приводит к каноническому ответу без повторного применения правил. Старый раздел «Следующая итерация» описывает целевое состояние: распознавание и синтез речи ещё не реализованы.

Node.js-шлюз проверен 20 локальными тестами. Реальный API, Unity-компиляция, UI и отмена из Unity ещё требуют редакторской проверки. CI запускает только Node.js-тесты. Не считать валидацию JSON доказательством смысловой корректности модели.
