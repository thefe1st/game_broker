# Рабочие дни: небольшое повторяемое продолжение

## Запуск и границы

1. Завершите три дня вводной главы. Подходит и ранее сохранённый итог этой главы.
2. В итогах нажмите **«Перейти к рабочим дням»** либо в меню **«Начать рабочие дни с дня 4»**.
3. Подтвердите копирование прогресса. Начнутся отдельные рабочие дни с номера 4.
4. После каждого дня нажимайте **«Следующий рабочий день»**. Сценарного финала по номеру дня здесь нет.

Для нового продолжения нужно завершённое вступление. При первом переходе копируются личные накопления ($0–330), репутация и отношения с тремя знакомыми клиентами; покупатели дня 3 ждут отчёт. Существующее продолжение открывается вместо повторного копирования. Вводная глава не меняется. Позднейший сброс вступления не мешает продолжать уже созданные рабочие дни.

Это первый небольшой повторяемый цикл, **не полная песочница**. Нет открытия своей фирмы, повышения, нового продукта, жалоб, рыночной симуляции или полноценной альтернативной системы мутных продаж. Городские поручения остаются скрыты. Экономика и переговоры локальные; API необязателен.

## Клиенты и расписание

Ежедневно доступны три контакта из постоянного пула шести. Расписание подготовленное, не случайная процедурная генерация; цикл из четырёх списков повторяется:

| День в цикле | Клиенты |
|---|---|
| 4, 8, 12… | Борис, Вера, Денис |
| 5, 9, 13… | Инна, Оксана, Вера |
| 6, 10, 14… | Артём, Денис, Оксана |
| 7, 11, 15… | Борис, Инна, Артём |

Каждому можно позвонить один раз за рабочий день, а не один раз за карьеру. День длится 10 игровых минут. Рабочий ориентир — **две сделки**, пока без штрафов или увольнения. Это тестовый баланс. Лена и Макс остаются коллегами, расходы фирмы не списываются с игрока.

Для всех нужны цель, риск убытка, комиссия 2% и отдельный ответ на возражение после предложения:

| Клиент | Комиссия фирмы / личная выплата | Дополнительное условие | Последний вопрос |
|---|---|---|---|
| Борис, автомойки | $150 / $30 | — | Резерв, не вкладывать всё |
| Инна, экс-финдиректор | $220 / $44 | Годовой срок | Письменный договор |
| Артём, наследник | $180 / $36 | Персональное сопровождение | Личный контакт |
| Вера, стоматология | $200 / $40 | — | Письменные условия и комиссия |
| Денис, пекарня | $170 / $34 | Годовой срок | Резерв на ремонт печи |
| Оксана, дизайнер | $190 / $38 | Персональное сопровождение | Письменный договор |

Новые персонажи имеют свои вступления, ответы, возражения и реакции на давление. Это по-прежнему словарные правила, не понимание естественного языка. Один синтетический голос остаётся общим; шлюз принимает все шесть ID, но настоящий внешний API не проверен.

## Отношения и отчёты

Состояние связано со стабильным ID клиента, **не номером кнопки в дневном списке**. Продажа даёт +1 отношения, закрытый звонок без продажи −1, отсутствие звонка ничего не меняет; диапазон прежний, от −1 до +2. Отношения влияют на стартовое доверие.

После каждой сделки появляется необсуждённый отчёт. Он не исчезает, если клиента нет в списке несколько дней или вы ему не позвонили. На следующем звонке сначала нужно сказать, например, **«Обсудим отчёт по прошлой сделке»**. Новая сделка заблокирована до обсуждения. Можно обсудить отчёт без новой продажи: старый запрос снимется, но закрытый без сделки звонок всё равно ухудшит отношение. Новая продажа создаст следующий запрос отчёта.

Это простое продолженное обязательство, не расчёт доходности инвестиций: прибыли/убытка продукта, документов и реальных жалоб пока нет. Текущее отношение видно в дневной карточке клиента. После дня показаны отношения всех шести клиентов и те, кто ждёт отчёт, плюс список завтрашних контактов.

## Отдельное сохранение

Файл: `Application.persistentDataPath/broker-employee-work-v1.json`, `schemaVersion=1`, `mode=employee-work`.

- Ни `broker-employee-intro-v1.json`, ни старый `broker-career-v1.json` не мигрируются/не перезаписываются.
- Сохранение только после завершения дня. При закрытии игры посреди дня последний незавершённый день начинается заново. Пауза при сворачивании — не сохранение.
- В файле остаются исходное перенесённое состояние, сводная контрольная точка и последние **семь** подробных дневных отчётов. Старые результаты сворачиваются в контрольную точку: деньги, отношения, число сделок и необсуждённые отчёты сохраняются, подробная старая история — нет.
- При загрузке валидируются версия/режим, состав клиентов, номера дней, суммы комиссий и личных выплат, затем из контрольной точки переигрываются сохранённые отчёты. Это проверка целостности, не защита от редактирования сохранений игроком.
- У режима собственные `.bak`/`.tmp`; восстановление не затирает здоровую `.bak` повреждённым основным файлом. Перед заменой неизвестной версии/нечитаемых данных сохраняется `.unreadable-*`.
- Если новый файл не записывается, переход остаётся на подтверждении и его можно повторить. После ошибки дневного сохранения можно повторить запись либо явно продолжить текущий запуск без записи; смена режима заблокирована до успешного сохранения.
- **«Сбросить рабочие дни»** с подтверждением возвращает к исходному состоянию перед днём 4, скопированному при первом переходе, а не заново читает изменённое вступление. Другие файлы не меняются.
- Нет игрового лимита «три дня». Технически номера и денежные поля всё ещё `Int32` с проверками допустимых границ; это не заявление о бесконечной числовой ёмкости.

## Проверка и ручной чек-лист

Вне Unity проверены 1000 последовательных дней с полными продажами, восстановлением состояния и переносом более $100000; сворачивание истории, отчёт через пропуски дней, перенос/отмена/сброс и ошибки записи. Общие актуальные числа тестов — в README.

Это **не запуск Unity**: FlowChecks заменяет сцену/GUI/JsonUtility; файловые проверки используют System.Text.Json на Linux. Настоящие компоновка, ввод, JsonUtility и File.Replace на Windows требуют проверки:

- [ ] Сделать внешнюю копию прежних файлов. Импорт в Unity 6000.3.14f1 без красных ошибок.
- [ ] До окончания вступления новый режим недоступен. После дня 3 отмена переноса не создаёт файл.
- [ ] Подтвердить перенос: день 4, прежние накопления, отдельный файл; вступление/владелец и их `.bak` не изменились.
- [ ] Проверить меню трёх режимов, утро/результаты в 1440×960 и Full HD: все подписи/предупреждения помещаются.
- [ ] Позвонить Вере и Денису на дне 4; Оксане на дне 5. Досье, специальные условия, отдельный ответ и выплаты $40/$34/$38 работают; дубль не платит.
- [ ] Продать Вере на дне 4: на дне 5 она переместилась с кнопки 2 на кнопку 3, но сохранила отношения/отчёт.
- [ ] Продать Борису на дне 4, пропустить его до дня 7: отчёт всё ещё обязателен. Обсудить без сделки и проверить снятие запроса.
- [ ] Пройти день 7 и дальше: нет финала вступления/автоматического открытия фирмы, номер дня растёт.
- [ ] Остановить Play посреди дня и после конца: незаконченный день заново, завершённый сохранён. Проверить JsonUtility после более семи дней.
- [ ] Сбросить вступление и повторить Play: существующее продолжение доступно. Сбросить только рабочие дни: возврат к исходному переносу, другие файлы не тронуты.
- [ ] Проверить `.bak`, повреждённую копию, повтор записи и переключение режимов на Windows. Проверить голос отдельно, не считать локальные заглушки проверкой API.
