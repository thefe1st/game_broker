# Материалы офиса и квартала

## Пиксельные поверхности

Сцена воксельная ([VOXEL_STYLE.md](VOXEL_STYLE.md)), все поверхности — пиксельные рисунки `VoxelSurfaces`:

| Ключ | Где используется |
|---|---|
| `pavers` | Плитка площади и тротуаров |
| `asphalt` | Бульвар |
| `concrete` | Бордюры, клумбы, уличные конструкции |
| `grass` | Газоны, сквер, грунт за кварталом |
| `wood` | Пол офиса, деревянные детали |
| `carpet` | Ковролин у стола директора |
| `plaster` | Стены офиса |
| `brick`, `concrete`, `plaster` | Простые фасадные коробки |
| `windows` | Дальняя застройка, три оттенка |

Каждый рисунок — **32×32 пикселя** из 2–6 цветов воксельной палитры, бесшовный и детерминированный. `SurfaceLibrary` строит текстуру кодом один раз на сцену и освобождает её вместе со сценой: файлов текстур в игре нет, при игре ничего не скачивается. Настройки: `FilterMode.Point` (чёткие пиксели), Repeat, mipmaps, anisotropic 2. Один повтор — **2 м**, окна — **6 м**.

`OfficeScene.Surfaces.cs` проецирует UV на грани процедурных кубов с учётом размеров и положения (`SurfaceMapping` в Core), поэтому длинная стена повторяет рисунок, а не растягивает одну картинку. Карт нормалей нет: рельеф дают геометрия вокселей и свет. Блеск задан числом, металличность 0. Для Standard и URP/Lit назначаются их собственные свойства цвета и гладкости; HDRP не поддерживается. Ключ без пиксельного рисунка оставляет однотонную поверхность и пишет одно предупреждение в консоль.

## Как изменить поверхность

1. Рисунок — в `VoxelSurfaces.Texel(key, x, y)`: индекс цвета палитры для каждого пикселя 32×32. Новый ключ добавить в список ключей там же.
2. Цвета — только из `VoxelPalette`, чтобы поверхности совпадали по тону с воксельными объектами.
3. Тесты `VoxelTests` проверяют бесшовность, детерминизм и число цветов. Кадр без Unity: `dotnet run --project Tools/ScenePreview/ScenePreview.csproj -c Release -- preview`.

## Прежние фото-текстуры

До 3 ноября офис и квартал использовали CC0-карты Poly Haven (дерево, штукатурка, бетон, асфальт, кирпич, трава) с картами нормалей, упакованные в `Assets/Broker/Resources/BrokerMaterials`. После перехода на пиксельные поверхности они не использовались и 3 ноября удалены вместе с реестрами `ThirdParty/` и скриптами импорта; восстановить можно из истории git (коммит `245191f`). Модуль `com.unity.modules.imageconversion` больше не нужен коду, но оставлен в `Packages/manifest.json`: без редактора его удаление не проверить.

## Проверить в Unity

- [ ] Нет красных ошибок и предупреждений «has no pixel pattern» в консоли.
- [ ] На полу, столах, стенах, плитке и асфальте видны чёткие пиксельные рисунки, а не белые или розовые поверхности.
- [ ] Вблизи нет сильного растяжения; вдали плитка и асфальт не рябят чрезмерно.
- [ ] Лифт туда/обратно, окна, площадь и все взаимодействия работают как раньше.
- [ ] Повторный Play не накапливает созданные Mesh/Texture2D в Profiler.
- [ ] Для standalone проверить, что Standard shader не исключён сборкой (Graphics → Always Included Shaders при необходимости).
