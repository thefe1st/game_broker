# Путь от прототипа к полной игре

## Последняя цель автора

21 октября 2026 автор попросил **полностью сделать игру по плану**, использовать бесплатные интернет-ассеты с правами на коммерческое применение или выдавать задания, по которым он сможет создать модели. Это расширяет цель за пределы доводки первого помощника. Разработка идёт законченными этапами, не одним неконтролируемым переписыванием. Новые числа/подробные правила ниже — рабочий дизайн ИИ, не ранее утверждённый баланс автора.

Последующее уточнение автора: больше реализма/механик, модели и текстуры не откладывать, **начать расширение города**. Добавлен отдельный пакет района с графикой и пешей навигацией, [CITY_DISTRICT.md](CITY_DISTRICT.md). Это обновляет приоритет графики/города; не отменяет карьеры/сохранений и не разрешает считать готовыми физику транспорта, интерьеры и рынок.

Существующие вводная глава, рабочие дни, контора и прежний owner остаются рабочими и совместимыми. Нечитаемые сохранения не стираем. Прогресс определяется C# Core, не внешней моделью. Базовая игра локальная, внешние ИИ/голос необязательны. Городские поручения остаются скрытыми; оживление квартала не подменяет карьеру.

## Рабочая граница полной первой версии

PC-игра на Unity 6000.3.14f1: личные продажи → карьерный рост/открытие → небольшая управляемая фирма → устойчивый повторяемый цикл развития и последствий. Есть достижимые цели, но нет обязательного конца через три дня или после основания. Приземлённая сатира, оригинальные персонажи и фирмы. Без мультиплеера, огромного открытого мира, биржевого терминала с реальными котировками и обязательной подписки на API.

Это целевой объём производства, **не описание уже готовых функций**. Целевая платформа сейчас Windows PC; другие платформы, публикация в магазине, цена и дата релиза не определены.

## Этапы и критерии готовности

| Этап | Что нужно получить | Когда этап считается готовым |
|---|---|---|
| **A. Визуальная база — текущий** | Единый воксельный стиль из кода (с 3 ноября вместо авторских моделей), пиксельные поверхности, закатный свет и дымка, подключение без потери взаимодействий | Воксельная сцена осмотрена в Unity по чек-листу [VOXEL_STYLE.md](VOXEL_STYLE.md), FPS приемлемый; офлайн-предпросмотр в CI. Скачивание при игре не требуется |
| **B. Настоящая небольшая команда** | Помощник и брокер с разными ролями, явные поручения, дневная стоимость и результат, ограниченная нагрузка; постепенно разгружать личный обзвон | Нельзя продавать одному контакту дважды/обходить обязательства; оплата/результат сохраняются один раз; понятное UI и долг. Новый формат отдельный, старые файлы read-only |
| **C. Клиенты и последствия** | Больше авторских ситуаций, сопровождение сделки, значимые обещания и жалобы, честная/рискованная стратегия с отложенными последствиями | Память по ID через отсутствие/перезапуск; выгода и цена решений понятны; модель только перефразирует канонический ответ. Не штрафовать произвольное слово вместо действия |
| **D. Развитие конторы** | Ограниченная вместимость, рабочие места/небольшое расширение, расходы и экономический выбор, восстановление из долга | Улучшение реально меняет доступную работу, не только число; нельзя бесконечно нанимать/получать деньги из меню; отсутствие софтлока при долге |
| **E. Рост наёмного брокера** | Возможность остаться в фирме и получить роль/ответственность, карьерный выбор внутри игры, а не только меню прототипов | Продолжение наёмной ветки имеет свои решения; открытие не принудительное; смена ветки не дублирует капитал. Старый owner не заменяет новую карьеру |
| **F. Долгая песочница и баланс** | Повторяемый цикл, контролируемая вариативность, конкуренция/события только с реальными решениями, долгосрочные цели | Серии дней дают новые решения, а не только имена; длительный прогон не ломает деньги/память; тестируется интерес игры, не только бухгалтерия |
| **G. Завершение PC-версии** | Настройки, интерфейс/обучение, звук/анимации, сохранения и восстановление, оптимизация, сборка, авторство/лицензии | Чистый импорт и standalone Windows, тест с нового профиля и прежними saves, без сети, разные разрешения/фокус/ввод; проверенный пакет сборки. Реальная Unity-проверка обязательна |

Порядок B→C→D связан с нынешней готовой конторой; альтернативу E делаем после укрепления основного цикла, не параллельно второй полноценной кампанией. Рыночные инструменты, увольнение, личные вложения и сложность конкурентов уточняются перед соответствующим этапом, не добавляются вместе только ради списка.

## Очередь ассетов

**Сейчас:** авторские модели не нужны — объекты делаются воксельными генераторами в коде ([VOXEL_STYLE.md](VOXEL_STYLE.md)). Задания [ART_BRIEF.md](ART_BRIEF.md) — необязательный резерв.

**После появления механики:** вариант маленького/расширенного офиса, дополнительное рабочее место, портреты клиентов, игровые документы/папки, вывеска. Не заказывать модель функции, которой пока нет.

**Позже:** вариации одежды сотрудников, ограниченный набор квартальных фасадов/машин, фоновая жизнь и звук. Не скачивать гигабайты несвязанных реалистичных пакетов и не смешивать случайные художественные стили.

## Технические проверки каждого этапа

1. Авторитетные правила в Core; добавить регрессии нового поведения и запретов. Сохранения с новыми полями — отдельная схема/файл и явное чтение старых без изменения байтов.
2. Bootstrap/Flow — переходы, пауза, отказ записи, отмена, повтор и exactly-once; не выдавать GUI-fakes за настоящий UI.
3. Прогон Core, Flow, Voice, Server и синтаксис Assets по четырём конфигурациям ввода. Сцена: `dotnet run --project Tools/ScenePreview/ScenePreview.csproj -c Release -- --check` (в CI — `scene-preview`).
4. Обновить README, правила, архитектуру и ручной чек-лист.
5. Автор проверяет Unity: импорт, Play, компоновка, физика, сериализация, затем standalone. Только после этого писать «проверено в Unity».

3 ноября по просьбе автора («дальше: котировки и разные комиссии») добавлены **котировки и ставки v4**. В рабочих днях и своей конторе у каждой из шести бумаг одна вымышленная цена на игровой день — детерминированная целочисленная функция дня в опубликованном коридоре, без реальных данных и сохранённого состояния рынка. Каталог показывает цену, изменение ко вчера, график за 7 дней и число целых акций на фиксированное вложение клиента. Комиссия зависит от риска: 2% — SVET/RLOG, 3% — MDAT/OBLK, 5% — NEDR/BIMP (например, Артём $180/$270/$450); игрок называет ставку выбранной бумаги. Возвращающийся клиент в отчёте видит цену покупки и сегодняшнюю («Цена не обещание»), это не меняет доверие и деньги. Схемы `broker-employee-work-v4.json`/`broker-founder-v4.json` хранят цену покупки и число сделок по 3%/5%, поэтому свёрнутые дни проверяются точно; v3/v2/v1 только читаются, импортированные дни остаются по 2% без цены. Вступление и owner не изменились (2%, без цен). Прогон: 771 Core (626 Assets + 145 Tools), 162 Flow, 16 Voice, 36 Server; 77 файлов × 4 конфигурации синтаксиса, 0 ошибок. Unity/JsonUtility не проверены. Портфель, дивиденды, продажа акций клиентом и продуктовые последствия падения цены остаются следующими этапами рынка.
