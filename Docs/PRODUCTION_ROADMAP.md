# Путь от прототипа к полной игре

## Последняя цель автора

21 октября 2026 автор попросил **полностью сделать игру по плану**, использовать бесплатные интернет-ассеты с правами на коммерческое применение или выдавать задания, по которым он сможет создать модели. Это расширяет цель за пределы доводки первого помощника. Разработка идёт законченными этапами, не одним неконтролируемым переписыванием. Новые числа/подробные правила ниже — рабочий дизайн ИИ, не ранее утверждённый баланс автора.

Последующее уточнение автора: больше реализма/механик, модели и текстуры не откладывать, **начать расширение города**. Добавлен отдельный пакет района с графикой и пешей навигацией, [CITY_DISTRICT.md](CITY_DISTRICT.md). Это обновляет приоритет графики/города; не отменяет карьеры/сохранений и не разрешает считать готовыми физику транспорта, интерьеры и рынок.

Существующие вводная глава, рабочие дни, контора и прежний owner остаются рабочими и совместимыми. Нечитаемые сохранения не стираем. Прогресс определяется C# Core, не внешней моделью. Базовая игра локальная, внешние ИИ/голос необязательны. Городские поручения остаются скрытыми; оживление квартала не подменяет карьеру.

## Рабочая граница полной первой версии

PC-игра на Unity 6000.3.14f1: личные продажи → карьерный рост/открытие → небольшая управляемая фирма → устойчивый повторяемый цикл развития и последствий. Есть достижимые цели, но нет обязательного конца через три дня или после основания. Приземлённая сатира, оригинальные персонажи и фирмы. Без мультиплеера, огромного открытого мира, биржевого терминала с реальными котировками и обязательной подписки на API.

Это целевой объём производства, **не описание уже готовых функций**. Целевая платформа сейчас Windows PC; другие платформы, публикация в магазине, цена и дата релиза не определены.

## Технические проверки каждого этапа

1. Авторитетные правила в Core; добавить регрессии нового поведения и запретов. Сохранения с новыми полями — отдельная схема/файл и явное чтение старых без изменения байтов.
2. Bootstrap/Flow — переходы, пауза, отказ записи, отмена, повтор и exactly-once; не выдавать GUI-fakes за настоящий UI.
3. Прогон Core, Flow, Voice, Server и синтаксис Assets по четырём конфигурациям ввода. Сцена: `dotnet run --project Tools/ScenePreview/ScenePreview.csproj -c Release -- --check` (в CI — `scene-preview`).
4. Обновить README, правила, архитектуру и ручной чек-лист.
5. Автор проверяет Unity: импорт, Play, компоновка, физика, сериализация, затем standalone. Только после этого писать «проверено в Unity».
