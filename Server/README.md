# Локальный шлюз диалогов

Нужен Node.js 24. Внешних npm-зависимостей нет. Это шлюз **для Unity Editor / desktop на том же компьютере**, не готовый публичный сервис и не WebGL-сервер.

## Проверка без ключей

```sh
cd Server
npm test
npm start
```

По умолчанию MODE=mock: `/dialogue` возвращает локальную каноническую реплику без вызова ИИ. В Unity включите «Локальный шлюз :8787» перед звонком. Без галочки игра вообще не обращается к серверу.

Проверка доступности: `http://127.0.0.1:8787/health`. Сервер слушает только loopback.

## Настоящая модель — необязательно

1. Скопируйте `.env.example` в `.env` внутри Server.
2. В этом локальном файле укажите `MODE=ai`, `API_KEY` и `MODEL` вашего провайдера.
3. Если нужно, задайте `API_BASE_URL`, например адрес совместимого API с окончанием `/v1/`.
4. Перезапустите `npm start`.

Провайдер должен поддерживать Chat Completions, `response_format: { type: "json_object" }` и `max_tokens`. Не все совместимые API и модели поддерживают эти параметры. Реальный провайдер пока не проверен. Ключ не вводится в чат, игру или репозиторий. Используйте локальную переменную окружения / .env. Затраты на выбранный API оплачиваются отдельно.

## Что делает модель

Пока **только перефразирует** ответ, сформированный правилами игры. Оценка смысла речи игрока остаётся по ключевым словам. Это переходный этап, не полноценный ИИ-клиент. Модель получает до 12 последних реплик, текущую фразу и канонический ответ. Деньги ей не передаются для изменения, и в ответе допустимо только поле `reply`.

Формат и длина проверяются, но смысл реплики не валидируется независимой моделью: ИИ всё ещё может исказить смысл. Поэтому не использовать этот прототип как финансовый тренажёр. Будущая семантическая оценка и пригодность продукта — отдельные задачи.

## Ошибки и ограничения

- Таймаут сервера: 8 секунд, Unity: 12 секунд.
- До 30 запросов в минуту на весь процесс; до двух одновременно.
- Тело запроса до 16 KiB, ответ провайдера до 32 KiB.
- Входная реплика до 500 символов, ответ модели до 400.
- При ошибке Unity показывает локальную каноническую реплику без повторного применения правил.
- При завершении звонка / дня запрос отменяется; устаревший ответ не добавляется после перезапуска.
- Кнопки отправки и сделки недоступны во время ожидания.
- Правила применяются **до** внешнего запроса; отмена не откатывает уже сказанную реплику.
- Сырые реплики и ключи сервер намеренно не пишет в логи. В режиме ai текст отправляется выбранному внешнему провайдеру.

Нет пользовательской авторизации, долговременной памяти, биллинга и защиты уровня публичного сервиса. Host-проверка, отсутствие CORS и loopback уменьшают доступ из браузеров, но не защищают от локальных процессов. Не публикуйте этот сервер через туннель и не меняйте привязку на 0.0.0.0 без отдельного проектирования авторизации и лимитов.

## API

`POST /dialogue`, Content-Type: application/json:

```json
{
  "clientId": "boris",
  "message": "Какая у вас цель?",
  "canonicalReply": "Борис: Нужны деньги на оборудование.",
  "history": [{ "role": "client", "text": "Слушаю вас." }]
}
```

Успех: `{"reply":"..."}`. Ошибки: 400/403/404/405/413/415/429/502/504 с коротким кодом без деталей провайдера. История вкладывается в user-сообщение, а не используется как системные API-роли.


## Голос: новая экспериментальная возможность

Добавлены `POST /transcribe` (audio/wav → JSON с text) и `POST /speech` (JSON с text → audio/wav). По умолчанию VOICE_MODE=disabled: маршруты вернут 503, а внешние вызовы не выполняются. Голос можно включить независимо от MODE=mock/ai. Требуется тот же API_KEY и провайдер по API_BASE_URL, который поддерживает оба аудиомаршрута. Текстовая совместимость с OpenAI API сама по себе не означает поддержку аудио.

В .env: VOICE_MODE=ai, API_KEY=ваш локальный ключ. STT_MODEL, TTS_MODEL и TTS_VOICE настраиваются отдельно. Значения из .env.example — примеры совместимых моделей, не гарантия доступности у любого провайдера. Реальный API пока не проверен. Не передавайте ключ в чат.

Ограничения: PCM16 WAV, 8–48 кГц, до двух каналов; запись до 20 секунд и до 2 MB, синтез до 30 секунд и до 2 MB. Unity сводит запись в mono. Вход для синтеза до 400 символов, распознанная реплика до 500. Таймаут аудиомаршрутов 25 секунд (Unity — 30). Общие лимиты 30 запросов в минуту и 2 одновременных запроса сохраняются для всех маршрутов. Один голосовой обмен обычно требует двух аудиозапросов плюс запрос диалога, если включён шлюз формулировок.

Исходный звук проходит через память и не сохраняется сервером. Внешний провайдер получает запись/текст и может иметь собственные правила хранения. При выключенном голосе Unity не начинает запись. После распознавания пользователь проверяет текст до применения игровых правил. При ожидании сети игровой таймер приостанавливается.

Всего локально выполнено 34 Node.js-теста, включая обработку WAV, аудиомаршруты и ошибки провайдера с подставным fetch. Это не проверка реального микрофона, звука или внешней модели. В Unity добавлены отдельные, пока не запущенные EditMode-тесты WAV-кодека.
